# 데모 시나리오 (환자 × 처방 → 경고)

> ⚠️ DEMO · 가상 데이터 · 실제 진료 사용 불가
> 아래 표는 실제 규칙 엔진(`POST /cdss/evaluate`)을 시드 데이터에 대해 실행해 얻은
> 결정론적 결과입니다. 시연 시 그대로 재현됩니다.

## 빠른 시연 경로

1. **환자 목록** → 환자 선택 → **처방(CPOE)** 진입
2. 중앙에서 약물 검색·추가 → 우측 **CDSS 경고**가 실시간 갱신
3. CRITICAL 경고가 있으면 **처방 서명** 시 override 사유 입력 모달
4. **감사 로그**에서 서명/override 이력 확인, **가이드라인 Q&A**로 RAG 시연

## 핵심 시연 포인트

- **등급 정렬·집계**: 경고는 CRITICAL→WARNING→INFO로 정렬되며, 가산 위험(고칼륨혈증 등)은
  쌍마다 띄우지 않고 하나로 **집계**해 경고 피로를 줄인다(P008).
- **결정론적·LLM 미사용**: 위 모든 경고는 규칙 엔진의 순수 함수 결과로, 동일 입력에 항상 동일하다.
- **Human-in-the-loop**: P003/P004/P009 등 CRITICAL 케이스는 override 사유 없이는 서명이 차단된다.
- **LLM 보조**: 경고의 [자세히] 버튼은 LLM 설명(키 없으면 mock, "참고용" 표시)을 보여준다.
- **RAG Q&A**: "페니실린 알레르기 폐렴 항생제?" → CAP 가이드라인 근거와 출처를 인용해 답변.
